# Learning from real author edits, without pretending to have memory

**Priority of signals:** user's explicit instruction now > their final edited draft > feedback from the same author on previous drafts > supported own-post patterns > peer techniques. The source should be preserved so a speculative style preference is not treated as confirmed.

## Four-way comparison after a revision

If the user provides (1) your proposed text and (2) what they actually posted, compare:
1. **Ideas removed or added:** Did they reject the thesis, or just the formulation? Don't conflate content with style.
2. **Voice correction:** What changed in sentence length, humor, jargon, degree of certainty or how it ends?
3. **Structural correction:** Did they move evidence earlier, remove a hook, add a caveat or tighten the payoff?
4. **Contextual correction:** Was this about one post's circumstances, rather than a stable personal preference?

Produce a short, testable rule with source/feedback date, and label it **PROPOSED** until the author approves it. A durable preference should be phrased so future drafts can be checked (e.g. "never add a CTA unless requested" rather than "be more authentic").

## Holdout tests

For reliable onboarding, use part of the own-post sample set to distill the card, then hold out 2–3 posts for evaluation. Test at least two distinct topics/formats. Compare predicted sentence rhythm, argument structure, stance, humor and formatting; show mismatches and revise the card with the author's approval. Do not merely reprint the held-out posts as proof.

## Persistence

Claude Code does not gain shared cross-session knowledge just because a skill declares a profile. Store to a user-authorized local/private path only, e.g. ~/.claude/voice-profiles/author_alpha.md. Never put sample writing or private personality in the team-distributed ZIP. When permission is absent, apply feedback to the current session only and say it is not durably stored.

If the user has multiple personas (personal account vs corporate account), maintain two distinct profiles even when both are operated by the same person.
